# Clay 1.14.0 compatibility review

Reviewed upstream `b9952b68b24f592bfc3b50b3b6e4ec4e7949467d` through `703099008a0e50016db4d79e96b2b66b21119410` for maintenance issue #6.

Only three monitored files changed:

- Plugin manifest: version 2.33.0 to 2.35.0.
- CLI minimum: 1.9.0 to 1.14.0. The Windows installer already discovers installed plugin minimum versions and passes the highest minimum to the official Linux installer.
- CLI skill: documents approval-required responses, approving/denying requests, and saved approval rules. It requires explicit user intent for `--always-allow`. The bridge forwards commands without granting approvals.

CLI 1.13.0 release notes concern workflow node inputs/schema/account mapping. CLI 1.14.0 adds approval rule commands and workflow budget names. Neither changes the bridge invocation contract. No monitored install, setup, or update scripts changed. The advertised v0.3.1 installer still matches main.

The November 4 automatic-release run passed Windows/Linux fixtures and the downloaded official 1.14.0 binary's digest, version, help, and forwarding checks: https://github.com/danielkupka/clay-cli-windows/actions/runs/41850147770

Refresh the reviewed baseline without changing bridge source, plugin files, or approval settings. PR CI must also pass before merging. This records bounded compatibility evidence; it does not verify every new Clay feature, live authentication, or a fresh WSL installation. Existing local installations are not updated by this baseline change; plugin 2.35.0 requires local CLI 1.14.0 or newer.
